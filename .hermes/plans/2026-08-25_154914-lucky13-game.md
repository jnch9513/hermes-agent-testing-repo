# 幸運十三張 (Lucky 13) Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 喺現有大廳 app（~/my-nextjs-app）加一個「幸運十三張」房 — 變體十三張：每 round 派牌後限時揀牌擺入頭/中/尾三道，擺咗唔准改，5 rounds 完成 13 張，最後開牌結算。

**Architecture:** Game state 全部 server-side（WS hub 內 per-room state machine），Redis 持久化 room/game state（跨 instance）。客戶端純 render + 送 frame。牌邏輯（洗牌、派牌、牌型判定、計分）係純 functions，獨立 module，可以單元測試。UI 用現有 shadcn + Vercel dark/light theme。

**Tech Stack:** Next.js 16 App Router、`ws` + `@vercel/functions` experimental_upgradeWebSocket、ioredis（Redis pub/sub + state）、shadcn/ui、Playwright headless 測試。

---

## 遊戲規則摘要（已同 KC 確認）

- **人數:** 2–4 人
- **牌:** 標準 52 張
- **三道:** 頭道 3 張、中道 5 張、尾道 5 張（3-5-5 鐵律；相道規則：頭 ≤ 中 ≤ 尾 牌型，違反 = 烏龍）
- **Rounds:**
  - R1: 每人派 5 張，全部要擺（例 1/2/2、3/1/1 都得，但總和必須 = 5，且不可超過該道剩餘空位）
  - R2–R4: 每人派 3 張，必須擺 2 張、棄 1 張（棄牌入棄牌堆，冇人見到）
  - R5: 棄牌堆剩餘派晒（每人最多 2 張），全擺
- **派牌順序:** 牌堆唔夠就先派晒牌堆（洗牌），再由棄牌堆補（棄牌堆派出前必須洗牌）
- **擺牌:** 上/中/下自由擺；擺咗落去鎖死唔改；每張牌即時公開（其他人見到你擺咗乜，但蓋住你未決定嘅手牌）；擺完 2 張後第 3 張 dim 畀玩家揀棄邊張
- **計時:** 每 round 派牌後倒數；玩家可以提前撳「準備好」；時間到自動用當前選擇（未擺夠就隨機/系統處理）
- **開牌:** 5 rounds 後全部開牌 → 相道檢查（烏龍判定）→ 特殊牌型檢查（MVP 先不做）→ 三道兩兩比拼 → 打槍(+x2)/全壘打(再 x2) → 加番（衝三+3、中葫蘆+2、中鐵支+8、尾鐵支+4、中同花順+10、尾同花順+5）→ 純分數記錄
- **特殊牌型（一條龍等 12 種）: MVP 之後先加**

## Stage Plan（KC 要求：分得細，每 stage 獨立可驗證）

### Stage 1: 純牌邏輯 core（無 UI、無 WS）
純 TypeScript functions，Vitest/簡單 assert 測試。

- [ ] **1.1 牌組表示**: `card.ts` — Card type (`{rank: 2-14, suit: '♠'|'♥'|'♦'|'♣'}`)，rank 14=A。52 張生成 + Fisher-Yates 洗牌。
- [ ] **1.2 Deck manager**: `deck.ts` — draw/shuffle/deal；「牌堆優先、唔夠由洗好嘅棄牌堆補」邏輯（對應 R4/R5 規則）。
- [ ] **1.3 牌型判定**: `handEval.ts` — 3 張道（一對/三條/烏龍）+ 5 張道（同花順＞鐵支＞葫蘆＞同花＞順子＞三條＞兩對＞一對＞烏龍）。回傳 `{type, rankValues[], tiebreak}` 可比較結構。A2345 最細順子、10JQKA 最大。
- [ ] **1.4 相道檢查**: `validateLayout.ts` — 三道牌數 = 3-5-5、頭道牌型 ≤ 中道 ≤ 尾道，違反回傳烏龍 flag。
- [ ] **1.5 計分 engine**: `scoring.ts` — 兩兩比三道（+1/-1 每道）、打槍（x2）、全壘打（再 x2）、加番（衝三+3、中葫蘆+2、中鐵支+8/尾+4、中同花順+10/尾+5）。N 人對戰產生 score matrix。
- [ ] **驗證:** node script 跑單元測試（或 `npx tsx`），所有 case 過。

### Stage 2: Game state machine（server-side，無 UI）
- [ ] **2.1 Room state types**: `types.ts` — GameState（phase: waiting/dealing/picking/reveal/scored）、PlayerHand、BoardSlots（top/mid/bot arrays）、DiscardPile、RoundInfo。
- [ ] **2.2 State transitions**: `engine.ts` — startGame(2-4 players)、dealRound()、placeCard(playerId, cardId, slot)、discardCard(playerId, cardId)、readyCheck、timerExpire()。全部 pure-ish（input state → new state），方便測試。
- [ ] **2.3 Timer**: 每 round 倒數（建議 45s R1 / 30s R2-4 / 20s R5 — 可 config），server tick 或 setTimeout；時間到 auto-place 剩餘（隨機合法位置）+ auto-discard。
- [ ] **2.4 Redis persistence**: game state serialize 入 Redis（key `game13:<roomId>`），跨 instance 重生；pub/sub channel 廣播 state diff。
- [ ] **驗證:** 模擬 4 人打完整場（fake timer），assert 最終 13 張 × 4 人、無重複牌、52 張帳目清楚。

### Stage 3: WS protocol + integration
- [ ] **3.1 Protocol frames**: `protocol.ts` 加 game frames — client→server: `game:create`, `game:join`, `game:start`, `game:place`, `game:discard`, `game:ready`；server→client: `game:state`（full snapshot per player，只含自己手牌明牌 + 其他人的公開牌/蓋牌數）、`game:event`（誰擺了牌到哪道、round 開始/結束、timer sync）。
- [ ] **3.2 Hub wiring**: presence-hub 加 game message routing；room `poker-a` 有 active game 時進入遊戲 view。
- [ ] **3.3 Snapshot 安全**: 每個 player 收到自己版本嘅 state（手牌明、其他人暗）— server-side filter。
- [ ] **驗證:** headless browser 2 人開局，完成 R1 擺牌流程。

### Stage 4: UI — 遊戲桌面
- [ ] **4.1 房間頁面**: `/room/[id]` route；poker-a 顯示幸運十三張桌。
- [ ] **4.2 手牌區**: 自己手牌（可點選）、擺牌模式（點牌 → 點上/中/尾格）、棄牌確認（dim 第 3 張 + 棄牌掣）。
- [ ] **4.3 公共區**: 三道 board（自己 + 對手各一份，對手擺牌動畫/即時更新）、牌堆/棄牌堆計數、round indicator、倒數計時條。
- [ ] **4.4 Ready 掣 + timer 自動**: 提前準備按鈕；時間到 server 強制結算 round。
- [ ] **4.5 結算畫面**: 全部開牌、逐道比拼結果、score matrix、加番/打槍/烏龍標示、「再嚟一鋪」。
- [ ] **驗證:** headless 2 人 full game screenshot 流程。

### Stage 5: Polish + deploy
- [ ] **5.1 烏龍提示**: 擺牌時如果已經不可能 3-5-5 / 相道必爆，警告但照准（規則係最後先判）。
- [ ] **5.2 斷線重連**: WS reconnect 後 request 最新 snapshot；斷線期間 timer 到照 auto-play。
- [ ] **5.3 Headless E2E**: 完整 2 人 + 4 人模擬賽跑一次，assert 無 exception、分數有變化。
- [ ] **5.4 問 KC → deploy.sh push**。

### Stage 6 (之後): 特殊牌型 12 種 + 長期積分榜

## Risks / tradeoffs / open questions

- **Vercel WS function duration**: 一場 game 幾分鐘，connection pinned 但有 max duration — reconnect + snapshot 機制（Stage 5.2）係必須，唔係 nice-to-have
- **Timer 準確性**: serverless instance 可能 idle reclaim；timer 以 Redis timestamp 為準（lazy expiry check on any event），唔靠 in-memory setTimeout 做真相
- **同時擺牌衝突**: 無（每人擺自己嘅道，無共享資源競爭）
